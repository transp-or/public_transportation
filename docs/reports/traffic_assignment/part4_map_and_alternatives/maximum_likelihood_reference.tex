\section{Maximum Likelihood as a Reference Estimator}

Maximum likelihood (ML) removes the prior contribution while retaining the
same demand parameterization, fixed-routing response, observations, and count
likelihood as the corresponding MAP fit.  It is therefore the appropriate
reference for assessing prior sensitivity.  A substantial ML--MAP difference
is expected when the likelihood is weak or the prior is informative; numerical
agreement is reassuring but does not establish identification or model
adequacy.

The current public gravity entry point is
\texttt{public\_transportation.inference.gravity.estimate\_gravity\_model}.
The estimator is configured with \texttt{GravityEstimatorConfig}; its default
optimizer is SciPy L--BFGS--B.  A gravity ML fit is obtained by omitting the
prior or setting the declared prior contribution to zero, while keeping every
other input identical to the MAP fit.  The general-purpose
\texttt{public\_transportation.estimation.maximum\_likelihood.run\_ml} engine
is available for compatible objective functions, but there is no current
public convenience function named
\texttt{compare\_reduced\_od\_likelihoods} or
\texttt{run\_reduced\_od\_prior\_sensitivity}; those names must not be used
as package interfaces.

Poisson and negative-binomial fits remain distinct observation models.  They
must use the same prepared response artifact, canonical data, initial point,
and parameterization, with likelihood-specific configuration where their raw
parameter layouts differ.  A negative-binomial improvement indicates
overdispersion relative to the Poisson mean--variance relationship; it does
not by itself validate the gravity form.

The current optimizer comparison is exposed by
\texttt{compare\_gravity\_optimizers}.  It runs SciPy L--BFGS--B and, when the
optional Biogeme dependencies are installed, the isolated TR--BFGS pilot on
the same objective, initial vector, scaling, and tolerances.  Each optimizer
has its own execution checkpoint, and the comparison reports termination,
objective, raw and scaled gradients, and precision diagnostics.  Biogeme is
optional and is not part of the default dependency set; an unavailable pilot
must therefore fail explicitly rather than silently changing the estimator.
