\subsection{Boundary-flow implementation contract}

The public gravity package implements the mathematical extension in
Section~\ref{sec:boundary-flow-observation-processes} through a deliberately
generic interface.  A case adapter may provide a
\path{GravityLinearMeasurementOperator} for each non-OD response block and
combine it with a \path{GravityAdditiveFlowBlock}.  The supplied direct and
linear non-negative flow models support, respectively, one grouped latent
parameter per flow and a lower-dimensional fixed basis.  A
\path{GravityJointParameterLayout} appends these parameters after the
ordinary gravity parameters with deterministic names, slices, transformations,
regularization, and a complete model fingerprint.

The primary OD operator remains the existing assignment operator.  Consequently
an OD-only case follows the legacy objective and result path byte-for-byte in
its mathematical inputs; boundary blocks are opt-in and change the model
identity only when they are configured.  Fixed boarding and alighting scales
are supplied by the observation-model contract and are aligned with the
canonical measurement-row order.  Event scales are not estimated in the
current implementation, avoiding their confounding with a global production
or detection scale.

Boundary matrices can be persisted as named companion artifacts.  Each artifact
stores its shape and numeric type, matrix/content hash, canonical row-order
fingerprint, boundary-group identifiers, parameter-layout and model
fingerprints, construction settings, schema version, and completion marker.
An unchanged OD artifact can therefore be reused when a boundary block is
added, while a changed boundary matrix, grouping, or row order fails closed
and requires a new joint fit.  Fit manifests and detailed reports retain the
OD, initial-onboard, terminal-outflow, fixed-offset, latent-total, and scaled
mean contributions separately.

The interpretation of a boundary cohort and the construction of its matrix
remain responsibilities of the case-specific adapter.  Estimated event
scales, type-specific dispersions, and route-wide survival or hazard models
are reserved for future extensions.

\subsection{Persisted residual audits}

Residual analysis is implemented as a report-only layer over persisted fit
artifacts.  The reusable API accepts a prediction table, an optional residual
table, an optional additive-contribution table, and case-owned metadata joined
by a stable observation identifier.  It does not activate preparation,
routing, an assignment operator, or an optimizer.  The command-line entry
point is
\path{python -m public_transportation.inference.residual_audit}; its output
contains deterministic JSON, CSV, and Markdown files together with SHA-256
input fingerprints and any available model and specification fingerprints.

For observation $r$, the audit recomputes the raw residual
$y_r-\widehat{y}_r$, a thresholded relative residual, the Pearson residual

\[
  \frac{y_r-\widehat{y}_r}
       {\sqrt{\max\{v_r,v_{\min}\}}},
\]

and the signed Poisson deviance residual.  A positive observation whose
predicted mean is at or below the declared floor is marked as a support
failure, near-zero prediction, and positive observation.  Such rows are
reported separately: they are not treated as ordinary large residuals and are
never removed automatically.

Any supplied metadata columns may define a grouping, including line, stop,
time regime, journey position, or boundary role.  Group summaries retain
explicit nulls when a denominator is unavailable.  When additive components
are present, the audit checks their total against the persisted predicted
value and reports OD, initial-onboard, terminal-outflow, fixed-offset, and
other declared contributions separately.  Boundary contributions are
measurement components, not conserved OD flows.

Two runs may be compared row by row only when their observation identifiers
and observed values agree; a subset comparison requires an explicit opt-in.
The comparison records prediction and residual differences, support-failure
changes, and grouped comparison metrics.  Fit-observation audits are not
independent validation.  A holdout interpretation is valid only when the
case owner supplies a genuinely independent observation set and records that
fact in the audit manifest.
